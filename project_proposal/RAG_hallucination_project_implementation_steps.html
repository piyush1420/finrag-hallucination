RAG Hallucination Project — Implementation Steps

Click each phase to expand the detailed actions. 6 phases total.

Phase 1 — Setup & data preparation
Weeks 1–2 · Before any modeling
▶
Environment setup
  • Create a shared GitHub repo — one per group, all members as collaborators
  • Set up a Python virtual environment with: langchain, faiss-cpu, sentence-transformers, openai, ragas, transformers, pandas, datasets
  • Store OpenAI API key safely in a .env file (never commit to GitHub)
  • Set up Google Colab notebooks linked to the same repo for GPU runs
Load and explore FinanceBench
  • Download the 150-example dataset from HuggingFace: PatronusAI/financebench
  • Load the two JSONL files: financebench_open_source.jsonl and financebench_document_information.jsonl
  • Merge on doc_name and inspect: question types, answer lengths, doc types (10-K vs 10-Q vs 8-K)
  • Download the source PDFs from the /pdfs/ folder in the GitHub repo
  • Do exploratory data analysis (EDA): distribution of question types, companies, answer categories — this feeds your preliminary paper
Document preprocessing & chunking
  • Extract text from each PDF using PyMuPDF or pdfplumber
  • Implement two chunking strategies: fixed-size (512 tokens) and sentence-aware chunking
  • Store chunks with metadata: company name, doc type, page number, chunk ID
  • Save processed chunks to disk so you don't re-process every run
Phase 2 — Build RAG pipelines
Weeks 2–3 · Core engineering work
▶
Pipeline 1 — Baseline RAG (BM25 sparse retrieval)
  • Index all chunks using rank_bm25 BM25 retriever
  • For each question: retrieve top-3 chunks, pass to GPT-3.5-turbo with a prompt template
  • Prompt template: "Answer the question using only the provided context. Context: {chunks}. Question: {question}"
  • Save all outputs: question, retrieved chunks, generated answer, gold answer
Pipeline 2 — Dense RAG (semantic retrieval)
  • Embed all chunks using sentence-transformers/all-MiniLM-L6-v2
  • Index embeddings in a FAISS flat index (faiss.IndexFlatL2)
  • For each question: embed the query, retrieve top-3 nearest chunks by cosine similarity
  • Use the same prompt template and GPT-3.5-turbo generator as Pipeline 1
  • Compare which chunks are retrieved vs BM25 — are they different?
Pipeline 3 — Enhanced RAG (query rewriting + dense retrieval)
  • Add a query rewriting step: prompt GPT-3.5-turbo to expand/rephrase each question before retrieval
  • Example rewrite prompt: "Rewrite this financial question to improve document retrieval: {question}"
  • Use the rewritten query to retrieve from the same FAISS index as Pipeline 2
  • Compare retrieval quality: do rewritten queries fetch better evidence?
Swap in Mistral-7B as alternative generator
  • Load mistralai/Mistral-7B-Instruct-v0.2 from HuggingFace with 4-bit quantization (bitsandbytes) on Colab GPU
  • Apply the best-performing retrieval config (from above) with Mistral as the generator
  • Use identical prompt template for fair comparison with GPT-3.5-turbo
  • Save all outputs in the same format for consistent evaluation
Phase 3 — Evaluation
Week 4 · Measuring what matters
▶
Automated metrics with RAGAS
  • Install and configure RAGAS: pip install ragas
  • Run three core metrics on each pipeline's outputs: faithfulness (is the answer grounded in retrieved context?), answer relevancy (does the answer address the question?), and context precision (are the retrieved chunks actually useful?)
  • RAGAS scores range 0–1; aim to report mean ± std across 150 examples per pipeline
  • Build a results DataFrame with columns: pipeline, model, faithfulness, answer_relevancy, context_precision
Standard QA metrics (F1 + Exact Match)
  • Implement token-level F1 and Exact Match (EM) against gold answers — standard SQuAD-style metrics
  • These complement RAGAS: F1/EM measure answer correctness, RAGAS measures groundedness
  • A high-faithfulness but low-F1 answer is grounded but wrong — interesting failure mode
  • Report both in your main results table for comparability with prior work
Identify failure cases for error analysis
  • Filter all outputs where faithfulness < 0.5 OR F1 = 0 — these are your hallucination candidates
  • From the baseline pipeline (Pipeline 1), sample 50 failure cases for manual annotation
  • Ensure the 50 cases cover a mix of question types and companies (stratified sample)
Phase 4 — Error analysis & hallucination taxonomy
Weeks 5–6 · The novel contribution
▶
Manual annotation of 50 failure cases
  • Each of the 4 group members annotates ~12–13 cases independently
  • For each failure: read the question, retrieved chunks, generated answer, and gold answer
  • Assign one hallucination type label (see taxonomy below)
  • Cross-check overlapping annotations on 10 shared cases to measure inter-annotator agreement (Cohen's kappa)
Hallucination taxonomy (4 categories)
  • Numerical hallucination — wrong figure, wrong unit, wrong year (e.g. says "$2.1B revenue" when correct is "$2.4B")
  • Entity hallucination — wrong company name, wrong executive, wrong product or subsidiary
  • Reasoning hallucination — logically flawed conclusion drawn from correct retrieved facts
  • Unsupported extrapolation — makes a claim not traceable to any retrieved chunk (pure fabrication)
Train RoBERTa hallucination classifier (optional but strong)
  • Use RAGTruth dataset as training supervision (available on HuggingFace: wandb/RAGTruth)
  • Fine-tune roberta-base as a binary classifier: hallucinated vs grounded
  • Input: concatenation of retrieved context + generated answer
  • Evaluate on your 50 manually annotated FinanceBench cases
  • Report precision, recall, F1 — how well does auto-detection match human judgment?
Phase 5 — Paper writing
Weeks 4–8 · Start early, revise often
▶
Preliminary paper (due 7/3) — 4 pages
  • Sections: introduction, related work (20–24 papers), data description + EDA, preliminary results with baseline pipeline only
  • Produce at least one results table and one figure (e.g. distribution of question types in FinanceBench)
  • Use the instructor-provided LaTeX or Word template — wrong template = zero
  • Divide writing: Person 1 owns intro + related work, others own methodology + results
Final paper (due 7/31) — 8 pages
  • Abstract (3–4 sentences: problem, approach, key findings)
  • Introduction: motivate RAG hallucination in finance, state research questions, summarize contributions
  • Related work: summarize 20–24 papers, grouped by theme (RAG methods, hallucination detection, financial NLP)
  • Methodology: describe all 3 pipelines, evaluation setup, annotation process
  • Results: main comparison table + hallucination type breakdown chart
  • Analysis: qualitative examples of each hallucination type, discussion of failure patterns
  • Conclusions + future work: what would the full 10K-example dataset reveal?
Figures and tables to produce
  • Table 1: main results — all pipeline × model combinations, RAGAS + F1 scores
  • Figure 1: bar chart of hallucination type frequencies (numerical vs entity vs reasoning vs unsupported)
  • Table 2: 2–3 qualitative examples per hallucination type (question, answer, gold, label)
  • Figure 2 (optional): RoBERTa classifier confusion matrix or precision/recall curve
Phase 6 — Presentation & poster
Week 9 · Due 8/4
▶
Poster design
  • Structure: motivation → research questions → pipeline diagram → results table → hallucination taxonomy → conclusions
  • Each group member owns one poster section matching their project role
  • Include a QR code linking to your video recording and GitHub repo
  • Keep text minimal — posters are visual; bullets over paragraphs
Video recording (max 8 minutes)
  • Each person presents ~2 minutes covering the part they owned
  • Suggested split: Person 1 = intro + motivation (2 min), Person 2 = pipeline design (2 min), Person 3 = results (2 min), Person 4 = error analysis + conclusions (2 min)
  • Record with slides (use poster sections as slides) and talking head
  • Hard cutoff at 8 minutes — practice beforehand, points deducted for going over
Workshop submission (bonus — resume value)
  • Check submission deadline for "Towards Knowledgeable Foundation Models" at ACL 2026
  • Format paper to ACL anthology style using the official ACL LaTeX template
  • Submit via OpenReview — submitting is free, presenting if accepted requires registration
  • Even a rejection gives you reviewer feedback and the line "submitted to ACL 2026 workshop" on your resume
